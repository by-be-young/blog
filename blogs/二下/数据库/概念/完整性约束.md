# 完整性约束概述

## 什么是数据库的完整性

完整性是指**数据的正确性和相容性**，防止不合语义的数据进入数据库。

例如学生的年龄必须是整数且取值范围为 14-29，学生的性别只能是男或女，学生的学号一定是唯一的，学生所在的系必须是学校开设的系。完整性关注的是数据是否真实地反映现实世界。

## 完整性控制机制

### 完整性约束条件定义机制

DBMS 应提供定义数据库完整性约束条件的方法

### 完整性检查机制

检查用户发出的操作请求是否违背了完整性约束条件

### 违约反应

如果发现用户的操作请求使数据违背了完整性约束条件，则采取一定的动作来保证数据的完整性。

# 完整性约束条件分类

## 按作用对象分类

完整性约束条件作用的对象分为三类：列（对属性的取值类型、范围、精度等的约束条件）、元组（对元组中各个属性列间的联系的约束）、关系（对若干元组间、关系集合上以及关系之间的联系的约束）。

## 按对象状态分类

- **静态约束**：反映数据库状态合理性的约束
    
- **动态约束**：反映数据库状态变迁的约束，涉及新值和旧值
    

## 六类完整性约束条件

静态列级约束、静态元组约束、静态关系约束、动态列级约束、动态元组约束、动态关系约束。

### 静态列级约束

对列的取值域的说明，如取值类型、取值范围、是否为空值等约束。

### 静态元组约束

规定元组的各个列之间的约束关系。

例如有 `订货关系（ID，商品，订货量，发货量）`，要求每条记录中 `发货量 ≤ 订货量`，用 Check 约束实现。

### 静态关系约束

关系的各个元组之间或若干关系之间存在的各种联系或约束，包括实体完整性约束、参照完整性约束、函数依赖约束、统计约束等。

例如 `工资表（职工 ID，工资，是否部门经理）`，要求 `职工平均工资的 2 倍 ≤ 部门经理的工资 ≤ 职工平均工资的 5 倍`，需用**触发器**实现。

### 动态列级约束

- **修改列定义时的约束**：例如将原来允许空值的列改为不允许空值时，若该列目前已存在空值，则拒绝这种修改（数据库自动实现）
    
- **修改列值时的约束**：修改列值时新旧值之间要满足的约束条件（使用**触发器**实现），例如职工工资调整 ≥ 原来工资，年龄只能增长
    

### 动态元组约束

修改元组值时各个字段之间要满足的约束条件。

例如职工工资调整不得低于其原来工资加工龄乘以 1.5，用**触发器**实现。

### 动态关系约束

对关系变化前后状态的限制条件，例如事务一致性、原子性等约束条件，在【并发控制-事务处理】部分讲解。

## 小结

| 约束类型     | **关键词（判断依据）**            | **典型例子**                                   |
| -------- | ------------------------ | ------------------------------------------ |
| **静态列级** | **单列**、**当前值**、取值范围/格式   | 工资 ≥ 0；性别只能为'男'/'女'；学号长度为12位               |
| **动态列级** | **单列**、**变化前后**、值的变化规则   | 工资**只能增加**不能减少；年龄**只能变大**                  |
| **静态元组** | **单行**、**当前行内**、多列间比较    | 实发工资 = 应发工资 - 扣款（同一行内）；结束日期 ≥ 开始日期         |
| **动态元组** | **单行**、**变化前后**、行内属性变化规则 | 修改工资时，**新的**基本工资必须 ≥ **旧的**基本工资 × 1.1      |
| **静态关系** | **多行**、**当前**、行与行之间的逻辑关系 | 部门经理的工资 **>** 该部门所有员工的工资；级别低的工资 < 级别高的工资   |
| **动态关系** | **多行**、**变化前后**、整体数据变更规则 | 更新经理工资后，**新的**经理工资 **>** 该部门所有员工**当前**最高工资 |

# 三大完整性约束

## 实体完整性约束

主键唯一且非空。

主键约束，确保每行数据的唯一性。

## 参照完整性约束

外键约束，确保表与表之间引用关系的正确性。

以上三类可以方便地在数据库中直接设置。

## 用户自定义完整性约束

其他复杂的完整性约束条件，往往需编程实现（触发器或 Check 等）。

# 完整性控制机制

## 完整性规则五元组表示

完整性规则可用五元组（D, O, A, C, P）表示：

- D（Data）：约束作用的数据对象
    
- O（Operation）：触发完整性检查的数据库操作，当用户发出什么操作请求时需要检查该完整性规则，是立即检查还是延迟检查
    
- A（Assertion）：数据对象必须满足的断言或语义约束，这是规则的主体
    
- C（Condition）：选择 A 作用的数据对象值的谓词
    
- P（Procedure）：违反完整性规则时触发的过程
    

例如在"学号不能为空"的约束中：D 为 Sno 属性，O 为插入或修改 Student 元组时，A 为 Sno 不能为空，C 无（A 可作用于所有记录的 Sno 属性），P 为拒绝执行该操作。

# 违约反应

## 实体完整性违约反应

违反实体完整性规则的操作一般是拒绝执行。

## 参照完整性违约反应

违反参照完整性的操作可以拒绝执行，也可以接受这个操作同时执行一些附加的操作以保证数据库的状态正确。

外键是否可以取空值依赖应用环境语义而定。

在被参照关系中删除元组时，若参照关系有若干元组的外键值与被删除的被参照关系的主键值相同，此时的违约反应可以是：

- **级联删除（CASCADES）**：一并删除参照关系中所有引用了被删除主键的元组
    
- **受限删除（RESTRICTED）**：只有当参照关系中没有任何元组的外键值与被删除的主键值相同时，才执行删除操作
    
- **置空值删除（NULLIFIES）**：将参照关系中所有引用了被删除主键的元组的外键值置为空
    

在参照关系中插入元组时，若被参照关系不存在相应的元组，则违约反应可以是受限插入或递归插入。

修改被参照关系中的主键，若主键在参照关系中已经被引用，则违约反应可以是级联修改、受限修改或置空值修改。

# 用户自定义约束的实现

## Check 约束

CHECK 约束通过限制输入到列中的值来强制域的完整性，常用于实现静态列级约束和静态元组约束。可以通过任何基于逻辑运算符返回 TRUE 或 FALSE 的逻辑表达式来创建 CHECK 约束。表达式可包含列名、比较运算符（>、<、=等）、逻辑运算符（and、or 等）、条件谓词（in、like 等），可使用 pattern（如_、%通配符，[]选择符等）。

示例：将 salary 列的取值范围限制在 15000 至 100000 之间，则 Check 约束为 `salary >= 15000 AND salary <= 100000`。检查 Email 字段的格式：`email like '%_@_%._%'`。学号是一个五位字符串，前二位为字符，后三位为数字，则可定义 CHECK 约束为 `SID like '__[0-9][0-9][0-9]'`。

## 触发器

### 触发器的定义

触发器用于实现复杂逻辑的用户自定义约束，是一种特殊的存储过程。它与表（或视图、数据库等）紧密相连，不能脱离宿主存在。由数据库自动调用执行，用户不能调用，没有参数和返回值。

### 触发器的 ECA 模型

触发器是一种 Event-Condition-Action 规则的实现：

- **Event 事件**：引起数据库更新的事件，如执行 Insert 语句向表中插入数据
    
- **Condition 条件**：判断是否满足条件的 SQL 表达式
    
- **Action 动作**：任意的 SQL 语句
    

### 触发器语法

```
CREATE [OR REPLACE] TRIGGER trigger_name
[BEFORE | AFTER | INSTEAD OF]
trigger_event ON table_reference
[FOR EACH ROW [WHEN trigger_condition]]
trigger_body;
```

### 触发事件

- 表/视图级事件：INSERT、DELETE、UPDATE
    
- 数据库级事件：CREATE、ALTER、DROP TABLE/PROCEDURE/VIEW 等
    

### 触发时机

- **AFTER**：在事件发生后触发
    
- **BEFORE**：在事件发生前触发
    
- **INSTEAD OF**：替换掉用户提交的操作语句，常用于不可更新视图的更新
    
MySQL 不支持 `INSTEAD OF` 触发器，也不支持在视图上建立触发器。

### 触发粒度

1. **语句级触发器**：每条用户语句触发一次。
    
2. **行级触发器（FOR EACH ROW）**：对于表中每条受影响记录，触发一次触发器。
  
例如执行 `Update stu set Gender='F'` 影响 500 条记录，语句级触发器触发和执行一次，行级触发器触发和执行 500 次。

### 引用新值和旧值

在触发器业务逻辑中可以通过引用来处理新值、旧值。名为"Inserted"的表包含新插入的行，名为"Deleted"的表包含删除的行。在 OpenGauss、MySQL 等数据库中可以直接使用关键字 NEW、OLD 来引用新、旧值：`NEW.Attribute`、`OLD.Attribute`。

### 触发器动作

用于实现自定义约束的业务逻辑，通常用于进行关联数据更新，不能返回查询结果。若需多于一条语句，则可用程序块实现：`Begin...End`。

拒绝更新的违约动作：引发系统错误，提示数据库拒绝更新，可用 `RaiseError`（SQL Server）、`Signal`（MySQL）、`Raise`（OpenGauss）函数。
