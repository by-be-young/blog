# 相关系统调用

| **系统调用**  | **主要操作步骤**                                              | **所需关键参数**                      |
| --------- | ------------------------------------------------------- | ------------------------------- |
| **创建文件**​ | 1. 在外存上找空闲空间  <br>2. 在指定目录中创建目录项                        | 文件路径、文件名、文件属性（如常规文件/目录）、初始大小/权限 |
| **删除文件**​ | 1. 在目录中查找目标文件目录项  <br>2. 回收其占用的磁盘块  <br>3. 从目录中删除该目录项   | 文件路径、文件名                        |
| **打开文件**​ | 1. 根据路径查找目录项  <br>2. 将目录项信息复制到内存的“打开文件表”中，并创建表项         | 文件路径、打开模式（如只读、只写、读写）            |

| **写文件**​  | 将内存用户缓冲区中的数据写回到外存对应的数据块中                                | 文件描述符、源内存缓冲区地址、要写入的字节数          |
# 文件目录

# 逻辑结构

逻辑结构指不同文件之间的排列规律。分为无结构文件和有结构文件。**此处只研究有结构文件**。

## 顺序文件

1. 链式存储；
2. 顺序存储。

链式存储的实现方式是单链表，而顺序存储的实现方式是数组，由于数组可以折半查找，顺序存储的顺序文件的查找速率比链式存储更高。

### 可变长记录和定长记录

可变长记录和定长记录都是顺序存储。

对于链式存储和可变长记录，无法随机存取；而对于定长记录，可以随机存取。

## 索引文件

使用一个索引表（自身是定长记录的顺序文件）：每个索引项指向一个记录，可对一个系统建立多个不同的索引。

平均查找长度：

$$ASL=\frac{\frac{1}{2}N(N+1)}{N}\approx \frac{N}{2}$$
## 索引顺序文件

一组记录对应一个索引项，记录内部是顺序存储。

也就是说，每个索引可以找到一组记录的第一个，然后再遍历整个组。这就要求组与组之间必须有一定的关键字顺序，而组内部则不需要。

$$ASL=\frac{1}{2}(索引组数+组项数)$$
## 多级索引文件

$$ASL=\sum每个索引表的项数$$
## 散列文件

通过哈希函数得到的键值（key）可以直接找到记录的物理地址（value）。查找极快，但难以避免冲突。

# 物理结构

物理结构指同一文件下物理块的**外存**组织方式。

## 连续分配

每个文件在磁盘块中占有一组连续的块。

采用连续分配时，逻辑文件中的记录也顺序存储在相邻的物理块中。

## 链接分配

这种分配方法可以让文件的盘块不连续，消除了磁盘的外碎片。

### 隐式链接

目录项中含有文件第一块的指针和最后一块的指针。

每个磁盘块中都有指向文件下一个盘块的指针。

### 显式链接

目录项中只有文件起始块号，磁盘块中也没有指针，而是采用文件分配表（FAT）的形式：

FAT 中的表项为盘块号+下一块的盘块号。从目录项中得知起始块号后，在 FAT 中一直往下查找，直到下一块的盘块号为-1 时表示文件结束。

## 索引分配

单独使用一个磁盘块用于存储整个文件的所有磁盘块号。

当文件太大而索引块太多时，和多级页表类似，也可以建立一个多级索引。

### 混合索引分配方式

文件太小，用一整个磁盘块存储索引非常浪费；文件太大，又需要多级索引才能存储。为了平衡各种大小的文件，可以采用混合索引分配方式。

在 FCB （Linux 和 UNIX 中以 inode 的形式实现）中，有若干个**直接块**和一级、二级甚至更高级的**间接块**。

直接块存放文件前几个磁盘块号。如果文件较小，就能够不浪费磁盘块建立索引；如果文件较大，则根据其实际需要，选择合适的多级间接块，找到主索引地址，再一级一级往下分配。

[question]
文件系统有三种典型的逻辑组织结构，包括连续文件、链接文件和索引文件。针对以下三类用户需求，请推荐一种最适合的文件结构，并给出解释。
1. 文件系统的性能主要取决于对于大文件的连续访问。
2. 文件系统的性能主要取决于对于大文件的随机访问。
3. 提高磁盘空间的利用率是文件系统的主要目标。
[\question]
[answer]
| 需求 | 推荐结构 | 核心理由 |
|------|----------|-----------|
| 1. 大文件的连续访问 | 连续文件 | 顺序读写时磁头移动最小，预读效率高，吞吐量最大 |
| 2. 大文件的随机访问 | 索引文件 | 通过索引直接计算物理块位置，避免链式顺序遍历 |
| 3. 提高磁盘空间利用率 | 链接文件 | 不连续存储，无外部碎片，空间浪费最小 |
[\answer]
[analysis]
**1. 大文件的连续访问 → 连续文件**：连续文件将数据块依次存放在连续扇区中。对于大文件的顺序读写，寻道次数极少，可充分利用磁盘带宽，吞吐量最高。链接文件和索引文件在连续访问时会有额外指针跳转或索引块读取开销。

**2. 大文件的随机访问 → 索引文件**：索引文件通过索引块保存所有逻辑块到物理块的映射。随机访问时可直接定位目标物理块，无需遍历。链接文件（隐式或显式）在随机访问时必须沿链表顺序遍历，效率极低（最坏 O (N) 次磁盘读）。连续文件在动态增长场景下难以维持连续性。

**3. 提高磁盘空间利用率 → 链接文件**：链接文件将数据存放在不连续的磁盘块中，通过指针链接，**无外部碎片**。连续文件会产生外部碎片导致空间浪费；索引文件需要额外索引块存储，对小文件存在额外开销。链接文件在空间利用率方面最优。
[\analysis]

# 文件共享

## 硬链接

文件目录的目录项不存放文件的物理地址等信息，而是放在索引节点（inode）中。

目录项为文件名和 inode 指针。通过 inode 指针找到 inode 后，inode 再提供文件的物理地址，从而找到文件。

同时，inode 中还有一个**链接计数** count，也称引用计数，用于表示有多少个用户目录项指向该 inode，即有多少个用户共享此文件。

## 软链接

其实就是给文件新建了一个“快捷方式”。如，用户 B 需要共享用户 A 的一个文件 F，系统会创建一个新文件 L，该文件会写入 B 的目录中，创建 B 的目录与 L 的链接。

而文件 L 中只包含 F 的路径，因此 B 找到 L 后就可以再找到 F 了。

[\question]
[options]A 正确[\options]
[options]B 错误[\options]
[answer]A[\answer]
[analysis]
硬链接：多个目录项指向同一个 inode（共享相同的 inode 号），删除其中任意一个硬链接只会减少 inode 的链接计数，只要计数不为 0，数据块就不会被释放，因此不影响数据完整性。

软链接：是一个独立文件，存储目标文件的路径，拥有自己的 inode 和数据块，类似于快捷方式。因此该说法正确。[\analysis]

# 文件系统挂载

文件系统在进程使用之前必须先安装，也称挂载。

文件系统都是基于根目录的，而根目录接在哪里，那就是挂载需要做的事情了。

挂载的时候，除了各种检查之外，还需要将超级块加载到内存中。

> 就比如，每棵树都有自己的根，但是却可以种在任何一片土地里。

[task]
[question]
文件系统挂载时，内核将该文件系统的超级块信息加载到内存中。
[\question]
[options]A 正确[\options]
[options]B 错误[\options]
[answer]A[\answer]
[analysis]
超级块（superblock）是文件系统的元数据核心，存储文件系统的关键信息，如文件系统类型、大小、空闲块数量、inode 数量等。当文件系统被挂载（mount）时，内核会将该文件系统的超级块从磁盘读取到内存中，并一直保留在内存中，以便后续对文件系统进行操作（如分配 inode、查找空闲块等）。因此该说法正确。[\analysis]
[\task]

# 总结：系统打开文件的流程

对于文件结构：

```text
file
├── file1
│   ├── .doc
│   └── .txt
└── file2
    └── .txt
```

以打开 `/file1/.doc` 为例：

1. 由于已经打开 `file`，此时 `file` 的目录已读内存；
2. 读取 `file` 的目录，以 `file1` 的文件名找到对应 `FCB`；
3. 根据不同的物理结构，用对应的方法找到对应的磁盘块；
4. 将目录项（FCB）复制到内存->内核区->打开文件表；
5. 开始读：将磁盘块的内容复制到内存->用户区。
