# 操作系统的发展历程

## 批处理系统

> 在最开始的手工操作阶段，由于没有操作系统，程序的装入、运行和结果输出等都需要人工干预，效率十分低下、CPU 的利用不充分，而且用户独占全机，资源利用率低。
> 
> 因此，操作系统应运而生，用告诉的机器代替手工操作来对作业进行控制。

为了解决人机矛盾及 CPU 和 I/O 设备之间速度不匹配的矛盾，出现了批处理系统。

### 单道批处理系统

1. 自动性
2. 顺序性
3. 单道性

### 多道批处理系统

> I/O 设备的速度远低于 CPU。
> 
> 正因为这个，在单道批处理系统中，如果一个作业在运行的过程中发送 I/O 请求后，CPU 就会等待 I/O 完成才能继续。
> 
> 因此，为什么不在发出 I/O 请求后，先运行其他的作业呢？

1. 多道
2. 宏观上并行
3. 微观上串行

多道批处理系统的资源利用率高、系统吞吐量大。

但用户响应的时间长、不提供人机交互能力。

## 分时操作系统

> 对于批处理系统，仍然存在两个致命的缺点：
> 
> - 无交互能力
> 
> 用户一旦把作业提交给系统之后，在作业完成之前，就无法再交互了。
> 
> - 用户独占主机
> 
> 当时计算机十分昂贵，人们既希望能够有独占主机的体验，又想共享主机，在不同终端上操作。

1. 同时性
2. 交互性
3. 独立性
4. 及时性

## 实时操作系统

> Charactex 要去日本！还有最后一张机票，赶紧用分时操作系统抢票！
> 
> 他提交购票请求后，系统把CPU时间片分给了其他进程，他的购票程序断断续续地执行。
> 
> 等终于轮到他把数据发出去时，后端返回“订单超时，已被释放”——他的操作已经错过了系统设定的响应窗口！
> 
> 为了解决这种对时间要求特别高的应用场景，就需要实时操作系统，它能保证关键任务在指定的截止时间前完成，不会因为被其他任务打断而延误。

实时操作系统分为硬实时系统和软实时系统。

# 操作系统的内核架构

## 宏内核

将系统的主要功能模块作为一个紧密联系的整体运行在内核态。

## 微内核

只将最基本的功能保留在内核，将那些不需要在内核态执行的功能移到用户态执行，从而降低内核设计的复杂性。

但是，微内核结构的主要问题是性能问题，因为需要频繁地在内核态和用户态之间进行切换，执行开销偏大。

[task]
[question]
宏内核操作系统的内核功能模块之间共享地址空间，能减少上下文切换开销。
[\question]
[options]A 正确[\options]
[options]B 错误[\options]
[answer]A[\answer]
[analysis]
宏内核将所有内核功能模块（如进程管理、内存管理、文件系统、设备驱动等）都放在同一个内核地址空间中运行。当用户程序通过系统调用进入内核时，不需要切换地址空间（只是从用户态切换到内核态，仍在内核地址空间），因此减少了上下文切换的开销。相比之下，微内核需要频繁的进程间通信（IPC）和地址空间切换，开销更大。因此该说法正确。[\analysis]
[\task]

# 系统调用

系统调用是操作系统提供给应用程序（程序员）使用的接口。系统调用属于**自陷**。

[task]
[question]
系统调用陷入与外部中断的处理流程完全相同，是操作系统获得 CPU 控制权的关键机制之一。
[\question]
[options]A 正确[\options]
[options]B 错误[\options]
[answer]B[\answer]
[analysis]
系统调用（陷入）与外部中断的处理流程**并不完全相同**。相同点是两者都会使 CPU 从用户态切换到内核态，操作系统获得控制权。不同点在于：系统调用是**同步**的、由程序主动发起的（通过 `syscall` 指令）；外部中断是**异步**的、由硬件设备随机触发（如时钟中断、键盘中断）。两者的入口地址、现场保存方式、返回机制等也可能存在差异。因此该说法错误。[\analysis]
[\task]

[task]
[question]
以下说法正确的是：
[\question]
[options]A 进程上下文切换过程一定会陷入内核[\options]
[options]B 陷入内核一定会导致进程切换[\options]
[options]C 正在执行的程序不可以主动放弃 CPU[\options]
[options]D 系统调用一定会导致进程上下文切换[\options]
[answer]A[\answer]
[analysis]
- 选项 A **正确**：进程上下文切换涉及保存当前进程的上下文（寄存器、程序计数器、栈指针等）并恢复另一个进程的上下文。这些操作需要特权级指令，必须在内核态执行，因此一定会陷入内核。
- 选项 B 错误：陷入内核（如系统调用、外部中断）并不一定会导致进程切换。例如，系统调用 `getpid()` 执行完毕后会立即返回原进程，不会切换进程。
- 选项 C 错误：正在执行的程序可以通过系统调用（如 `sched_yield()`）主动放弃 CPU。
- 选项 D 错误：系统调用不一定导致进程上下文切换，大部分系统调用返回时仍在原进程执行。[\analysis]
[\task]

[task]
[question]
进程因从网络设备读取数据包而阻塞，然后调度程序将该进程换出。这是一个自愿上下文切换的例子。（）
[\question]
[options]A 正确[\options]
[options]B 错误[\options]
[answer]A[\answer]
[analysis]
上下文切换分为自愿和非自愿两种。**自愿上下文切换**是进程主动让出 CPU，例如进程执行 I/O 操作（如 `read()` 系统调用）、调用 `sleep()` 或 `sched_yield()` 等。进程因从网络设备读取数据包而阻塞（等待数据到达），是进程主动发起的系统调用导致自己进入阻塞状态，从而触发调度程序切换出该进程，属于**自愿上下文切换**。非自愿上下文切换是由于时间片用完或被更高优先级进程抢占而被迫让出 CPU。因此该说法正确。[\analysis]
[\task]

[task]
[question]
操作系统在执行系统调用时可以被中断。（）
[\question]
[options]A 正确[\options]
[options]B 错误[\options]
[answer]A[\answer]
[analysis]
系统调用执行期间，操作系统处于内核态。此时外部中断（如时钟中断、设备 I/O 中断）仍然可以被响应，因为中断是比系统调用更高优先级的异步事件。操作系统通常会在系统调用执行过程中适当的时候（如完成临界区操作后）检查并响应中断。因此，操作系统在执行系统调用时**可以被中断**。该说法正确。[\analysis]
[\task]
