# I/O 设备的分类

## 按传输速度分类

1. 低俗设备；
2. 中速设备；
3. 高速设备。

## 按数据组织分类

1. **块设备**：以数据块为单位存储、传输信息。传输速率较高、可寻址；
2. **字符设备**：以字符为单位存储、传输信息。传输速率较低、不可寻址。

## 按用途分类

1. 存储设备：磁盘、磁带等；
2. 传输设备：网卡、Modem 等；
3. 人机交互器：键盘、鼠标、显示器等。

## 从资源分配角度分类

1. 独占设备：在一段时间内只能由一个进程使用的设备；
2. 共享设备：在一段时间内允许多个进程共同使用的设备；
3. 虚设备：用一类设备模拟另一类设备。

# I/O 控制器

## I/O 控制器的组成

### 与 CPU 的接口

用于实现 CPU 与控制器的通信。该类接口有三种信号线：数据线（传送读写数据）、地址线（要访问 IO 接口中的寄存器编号）、控制线（传送读写等控制信号）。

### 与设备的接口

一个设备控制器通常能够与多个设备相联，因此通常有多个与设备的接口。设备接口可传输数据、控制和状态三种信号。

### IO 逻辑

用于实现 CPU 对于 IO 设备的控制，通过一组控制线与 CPU 进行交互，对从 CPU 收到的指令进行译码。

设备控制器有以下几个主要功能：接收和识别 CPU 命令、进行数据交换（包括 CPU 与控制器、控制器与设备之间）、设备状态的了解和报告、设备地址识别、数据缓冲。

## 寄存器

可以被 CPU 直接访问的**寄存器**，主要有：

1. 数据寄存器：缓存从**设备发送**来的输入数据或 **CPU 发送**来的输出数据；
2. 状态寄存器：保存设备的执行结果或状态，供 CPU **读取**；
3. 控制寄存器：由 CPU **写入**，用于启动命令或更改设备模式。

# I/O 控制方式

## 程序直接控制方式

又称“轮询方式、程序查询方式”，CPU 主动不断地检查外设状态是否准备好。在设备较少、交互不频繁的场景下实现简单，但会占用大量 CPU 时间，效率较低。

## 中断驱动方式

外设准备就绪后向 CPU 发出中断信号，CPU 暂停当前任务处理 I/O 操作，相比轮询更高效。适用于响应及时性要求较高的系统，能够显著降低 CPU 的无效等待。

## DMA 方式

即“直接内存访问”，在数据量大、频繁传输的场景中尤为高效。CPU 只负责启动 DMA 控制器，数据传输过程由 DMA 独立完成，显著提高系统整体效率。

## 通道控制方式

由专门的 I/O 通道（可视为专用处理器）管理 I/O 操作，CPU 干预程度最低，只需发出 I/O 指令即可。
