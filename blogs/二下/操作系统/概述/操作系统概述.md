# 操作系统的概念和功能

> Young 按下电脑电源键，电脑就自己开机了，桌面上有多种多样的应用图标，只需要双击图标，居然电脑就能打开对应的软件！
> 
> 软件的数据、程序等明明存放在硬盘中，但我们不需要告诉电脑在硬盘的哪个位置，电脑居然就能找到。
> 
> Young 准备同时打开 QQ 和微信和不同的人聊天！这两个应用居然毫无影响，甚至可以同时发消息而不用排队！
> 
> 明明电脑只有一个 CPU，为什么可以“同时”干两件事而互不干扰？
> 
> ……
> 
> 其实，这些都是操作系统的作用。但是操作系统做的事可远不止这些！

#### 操作系统是控制和管理计算机资源（包括硬件、软件等）的软件。

简单来说，操作系统就是用户与计算机硬件系统之间的**接口**，用户只需提供最简单的命令，操作系统来完成底层功能，而不需要用户操心。

> 比如，现在基本都会有 GUI（图形用户界面），用户只需要点击屏幕上的按钮，就能发出命令，调用程序接口，等待操作系统完成功能即可。

## 进程管理（处理机管理）

> 微信和 QQ 可以同时打开，同时接收和发送消息，而几乎感觉不到有排队。但实际上，CPU 同时只能处理一件事。要想让两个程序几乎可以同时运行，就得要有合适的算法进行安排。
> 
> 同时，要防止两个程序之间相互干扰、互相独立，又要保证不同程序之间能共用某些数据，也是进程管理需要考虑的。

后续会讲到，处理机（CPU）分配和运行的基本单位是进程（或线程），因此处理机管理本质是进程管理。

主要包括进程控制、进程同步、进程通信、死锁处理、处理机调度等。

## 内存管理

> “内存”和我们日常生活中说的“手机内存”其实不是一个东西。你可能会听到某手机有 512 G 的内存，也可能会听到某电脑有 16 G 的内存。电脑的内存怎么会比手机小这么多呢？
> 
> 其实，我们说的手机内存（实际应该叫**外存**）指的是手机硬盘的容量，而内存指的是程序运行所需的临时空间。因此二者指代的东西不同，无法进行比较。

> 我们在运行程序时，如何通过内存中的数据找到硬盘中对应的指令或数据？如果内存满了，该如何清理不再需要的内存空间呢？这都是内存管理需要考虑的。

内存管理，是为了给多道程序的运行提供良好的环境、方便用户使用、以及提高内存的提供效率。

主要包括内存分配与回收、地址映射、内存保护与共享、内存扩充等。

## 文件管理

> 打开“我的电脑”，里面有若干磁盘和目录，一层一层点击目录，就能够找到你想要的文件，然后打开。
> 
> 这看起来非常理所应当，但是实际上的实现方式可不简单。文件是存储在磁盘中的，电脑如何找到这个文件？目录又如何记录自己包含了哪些文件？这些都是文件管理干的事。

文件管理主要包括文件存储空间的管理、目录管理、文件读写管理和保护等。

## 设备管理

> 用键盘敲下按键，屏幕就会显示出对应的字母；连接上打印机，点击“打印”按钮，就能将屏幕中的文档打印成纸上的文字。
> 
> 我们不用真正知道电脑是如何与这些设备进行“交流”的，因为操作系统的设备管理就能帮我们做到。

设备管理的主要任务是完成用户的 I/O（输入/输出）请求，方便用户使用各种设备，提高设备的利用率。

主要包括缓冲管理、目录管理、设备处理、虚拟设备等。

# 操作系统的特征

1. 并发（详见进程管理）
2. 共享（详见进程管理）
3. 虚拟（包括虚拟处理器、虚拟存储器、虚拟设备等）
4. 异步

#### 并发和共享是操作系统两个最基本的特征，二者相互依存。

# 操作系统的发展历程

## 批处理系统

> 在最开始的手工操作阶段，由于没有操作系统，程序的装入、运行和结果输出等都需要人工干预，效率十分低下、CPU 的利用不充分，而且用户独占全机，资源利用率低。
> 
> 因此，操作系统应运而生，用告诉的机器代替手工操作来对作业进行控制。

为了解决人机矛盾及 CPU 和 I/O 设备之间速度不匹配的矛盾，出现了批处理系统。

### 单道批处理系统

1. 自动性
2. 顺序性
3. 单道性

### 多道批处理系统

> I/O 设备的速度远低于 CPU。
> 
> 正因为这个，在单道批处理系统中，如果一个作业在运行的过程中发送 I/O 请求后，CPU 就会等待 I/O 完成才能继续。
> 
> 因此，为什么不在发出 I/O 请求后，先运行其他的作业呢？

1. 多道
2. 宏观上并行
3. 微观上串行

多道批处理系统的资源利用率高、系统吞吐量大。

但用户响应的时间长、不提供人机交互能力。

多道程序最早是为了解决早期单用户批处理系统 CPU 资源的浪费问题而提出的。
[\question]
[options]A 正确[\options]

早期单用户批处理系统中，CPU 与 I/O 设备串行工作，当程序进行 I/O 操作时 CPU 处于空闲等待状态，造成 CPU 资源浪费。多道程序设计技术允许在内存中同时装入多道程序，当一道程序进行 I/O 操作时，CPU 可以切换到另一道程序执行，从而提高了 CPU 利用率。因此该说法正确。[\analysis]

## 分时操作系统

> 对于批处理系统，仍然存在两个致命的缺点：
> 
> - 无交互能力
> 
> 用户一旦把作业提交给系统之后，在作业完成之前，就无法再交互了。
> 
> - 用户独占主机
> 
> 当时计算机十分昂贵，人们既希望能够有独占主机的体验，又想共享主机，在不同终端上操作。

1. 同时性
2. 交互性
3. 独立性
4. 及时性

## 实时操作系统

> Charactex 要去日本！还有最后一张机票，赶紧用分时操作系统抢票！
> 
> 他提交购票请求后，系统把CPU时间片分给了其他进程，他的购票程序断断续续地执行。
> 
> 等终于轮到他把数据发出去时，后端返回“订单超时，已被释放”——他的操作已经错过了系统设定的响应窗口！
> 
> 为了解决这种对时间要求特别高的应用场景，就需要实时操作系统，它能保证关键任务在指定的截止时间前完成，不会因为被其他任务打断而延误。

实时操作系统分为硬实时系统和软实时系统。

# 用户态与内核态【!】

> 这个真的超级重要！这个没有一个大致的印象，那么后面开始编写代码之后就会一头雾水。

## 特权级

为了保证系统安全，防止恶意程序破坏或用户不小心操作，处理器（CPU）在执行指令时，需要区分**特权级**。

x86 架构共分为 0 ~ 3 共 4 个特权级，其中 Linux 和 Windows 操作系统主要只使用 Ring 0（**内核态**）与 Ring 3（**用户态**）两个特权级，其他几乎不适用。

## 内核态

内核态具有**最高权限**。可以执行所有指令，包括特权指令，如 I/O 指令、内存清零指令等。

## 用户态

用户态具有**最低权限**。仅能执行非特权指令，仅能访问用户专属的地址空间，无法直接访问软硬件资源。

## 内核态与用户态之间的切换

由于内核态可以执行特权指令，因此只需要执行一个**返回指令**，就能从内核态切换到用户态。

但是用户态切换到内核态就没有那么简单了。内核态不能直接执行切换特权级的指令，因此只能通过主动发送请求或者被动切换。（详见后文[[#中断和异常]]）

# 操作系统的内核架构

## 宏内核

将系统的主要功能模块作为一个紧密联系的整体运行在内核态。

这样做的好处是，由于各个模块都在内核态，彼此可以共享信息、相互协助，在性能上具有很大优势。

> 但是，由于如今操作系统需要做到的功能越来越复杂，扩展系统时必须要重新修改内核代码，非常不方便。
> 
> 能不能直接在用户空间增加新服务，而不用改变内核代码呢？

[task]
[question]
宏内核操作系统的内核功能模块之间共享地址空间，能减少上下文切换开销。
[\question]
[options]A 正确[\options]
[options]B 错误[\options]
[answer]A[\answer]
[analysis]
宏内核将所有内核功能模块（如进程管理、内存管理、文件系统、设备驱动等）都放在同一个内核地址空间中运行。当用户程序通过系统调用进入内核时，不需要切换地址空间（只是从用户态切换到内核态，仍在内核地址空间），因此减少了上下文切换的开销。相比之下，微内核需要频繁的进程间通信（IPC）和地址空间切换，开销更大。因此该说法正确。[\analysis]
[\task]

## 微内核

只将最基本的功能保留在内核，将那些不需要在内核态执行的功能移到用户态执行，从而降低内核设计的复杂性。

但是，微内核结构的主要问题是性能问题，因为需要频繁地在内核态和用户态之间进行切换，执行开销偏大。

> 我们的实验中部分板块采用的是微内核的设计思想，这会导致部分功能在实现上会有些奇怪或者麻烦的地方，可能需要花更多时间进行研究。

# 中断和异常

#### 中断和异常是由用户态切换为内核态的主要手段。

发生中断或异常时，操作系统将陷入内核态进行处理，处理完毕后返回用户态继续执行用户态的指令。

## 中断

狭义的中断也称外中断，如 I/O 结束中断等。

中断分为可屏蔽中断和不可屏蔽中断。

## 异常

也称内中断，分为故障、自陷和终止。

![[中断的分类.jpg]]

## 系统调用

系统调用是操作系统提供给应用程序（程序员）使用的接口。系统调用属于**自陷**。

[task]
[question]
系统调用陷入与外部中断的处理流程完全相同，是操作系统获得 CPU 控制权的关键机制之一。
[\question]
[options]A 正确[\options]
[options]B 错误[\options]
[answer]B[\answer]
[analysis]
系统调用（陷入）与外部中断的处理流程**并不完全相同**。相同点是两者都会使 CPU 从用户态切换到内核态，操作系统获得控制权。不同点在于：系统调用是**同步**的、由程序主动发起的（通过 `syscall` 指令）；外部中断是**异步**的、由硬件设备随机触发（如时钟中断、键盘中断）。两者的入口地址、现场保存方式、返回机制等也可能存在差异。因此该说法错误。[\analysis]
[\task]

[task]
[question]
以下说法正确的是：
[\question]
[options]A 进程上下文切换过程一定会陷入内核[\options]
[options]B 陷入内核一定会导致进程切换[\options]
[options]C 正在执行的程序不可以主动放弃 CPU[\options]
[options]D 系统调用一定会导致进程上下文切换[\options]
[answer]A[\answer]
[analysis]
- 选项 A **正确**：进程上下文切换涉及保存当前进程的上下文（寄存器、程序计数器、栈指针等）并恢复另一个进程的上下文。这些操作需要特权级指令，必须在内核态执行，因此一定会陷入内核。
- 选项 B 错误：陷入内核（如系统调用、外部中断）并不一定会导致进程切换。例如，系统调用 `getpid()` 执行完毕后会立即返回原进程，不会切换进程。
- 选项 C 错误：正在执行的程序可以通过系统调用（如 `sched_yield()`）主动放弃 CPU。
- 选项 D 错误：系统调用不一定导致进程上下文切换，大部分系统调用返回时仍在原进程执行。[\analysis]
[\task]

上下文切换分为自愿和非自愿两种。**自愿上下文切换**是进程主动让出 CPU，例如进程执行 I/O 操作（如 `read()` 系统调用）、调用 `sleep()` 或 `sched_yield()` 等。进程因从网络设备读取数据包而阻塞（等待数据到达），是进程主动发起的系统调用导致自己进入阻塞状态，从而触发调度程序切换出该进程，属于**自愿上下文切换**。非自愿上下文切换是由于时间片用完或被更高优先级进程抢占而被迫让出 CPU。因此该说法正确。[\analysis]

[question]
操作系统在执行系统调用时可以被中断。（）
[\question]
[options]A 正确[\options]
[options]B 错误[\options]
[answer]A[\answer]
[analysis]
系统调用执行期间，操作系统处于内核态。此时外部中断（如时钟中断、设备 I/O 中断）仍然可以被响应，因为中断是比系统调用更高优先级的异步事件。操作系统通常会在系统调用执行过程中适当的时候（如完成临界区操作后）检查并响应中断。因此，操作系统在执行系统调用时**可以被中断**。该说法正确。[\analysis]
