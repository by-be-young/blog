# 基本概念与目标文件

## 什么是链接

链接是将各种代码和数据片段收集并组合成为一个单一文件的过程，这个文件可被加载到内存并执行

链接使得分离编译成为可能，支持多人协作开发

链接主要分为静态链接（编译时完成）和动态链接（加载时或运行时完成）

## 目标文件的三种形式

### 可重定位目标文件

扩展名为 `.o`，包含二进制代码和数据，其形式可以在编译时与其他可重定位目标文件合并，创建一个可执行目标文件

每一个 `.c` 源文件经过编译和汇编后产生一个对应的 `.o` 文件

### 可执行目标文件

Linux 中常无扩展名或为 `a.out`，Windows 中为 `.exe`

包含可直接复制到内存并执行的二进制代码和数据，与可重定位目标文件的关键区别在于其代码和数据已经分配了具体的运行时内存地址

### 共享目标文件

一种特殊类型的可重定位目标文件，可以在加载或运行时被动态地加载进内存并链接

Linux 中，静态链接库为 `.a`，动态链接库为 `.so`；Windows 中分别为 `.lib` 和 `.dll`

## ELF 文件格式

现代 Linux/Unix 系统的标准目标文件格式，统一了可重定位、可执行和共享目标文件

可用 `readelf` 命令查看其内容

ELF 文件由 ELF 头、多个节（Section）和节头部表组成

### 主要节区

`.text` 节存放已编译程序的机器代码

`.rodata` 节存放只读数据

`.data` 节存放已初始化的全局变量和静态变量

`.bss` 节存放未初始化或初始化为 0 的全局变量和静态变量（在文件中不占实际空间，仅为占位符）

`.symtab` 节为符号表，存放程序中定义和引用的函数和全局变量的信息

`.rel.text` 和 `.rel.data` 节分别存放代码和数据的重定位信息

`.debug` 和 `.line` 节存放调试信息（`gcc -g` 时生成）

`.strtab` 节为字符串表

# 符号解析

## 符号与符号表

符号主要分为三类：全局符号（模块定义并能被其他模块引用）、外部符号（其他模块定义并被本模块引用）、局部符号（仅被本模块定义和引用，如 `static` 变量）

符号表由汇编器构造，记录每个符号的名字、地址、大小、类型和绑定信息

对于可重定位目标文件，符号地址是距其所在节起始位置的偏移；对于可执行文件，符号地址是绝对运行时地址

## 符号解析规则

链接器的核心任务之一是将每个符号引用与一个符号定义关联起来

局部符号的解析简单明了，因为定义和引用在同一模块内

全局符号的解析较为复杂，若当前模块未定义，编译器会生成一个链接器符号表条目，由链接器在其他模块中寻找定义

### 多重定义全局符号的解析

全局符号分为强符号（函数和已初始化的全局变量）和弱符号（未初始化的全局变量）

链接器按三条规则处理：

1.  不允许有多个同名的强符号
2.  若有一个强符号和多个弱符号同名，选择强符号
3.  若有多个弱符号同名，从中任意选择一个

使用 `gcc -fno-common` 选项可以在遇到多重定义的全局符号时引发错误

## 静态库链接

静态库（`.a` 文件）是相关目标模块（`.o` 文件）的集合

链接时，链接器只复制被程序引用的库中目标模块，这减少了可执行文件的大小

### 链接器解析引用算法

链接器维护三个集合：将被合并的可重定位文件集合 `E`、未解析符号集合 `U`、已定义符号集合 `D`

按命令行顺序扫描文件：
*   若为 `.o` 文件，直接加入 `E`，并更新 `U` 和 `D`
*   若为 `.a` 文件，则尝试用其成员定义的符号解析 `U` 中的符号。若某个成员 `m` 定义了 `U` 中引用的符号，则将 `m` 加入 `E`，并更新 `U` 和 `D`。重复此过程直到 `U` 和 `D` 不再变化

扫描结束后，若 `U` 非空则报错；否则合并 `E` 中所有文件，生成可执行文件

### 命令行顺序的重要性

定义符号的库必须出现在引用该符号的目标文件之后

库文件通常应放在命令行的末尾

若库之间存在相互依赖，则必须排序，使得对于每个被存档文件成员外部引用的符号 `s`，在命令行中至少有一个 `s` 的定义是在对 `s` 的引用之后

[task]
[question]
对于以下依赖关系，给出最小的链接命令行。

A. p.o -> libx. A

B. p.o -> libx. A -> liby. A

C. p.o -> libx. A -> liby. A 且 liby. A -> libx. A -> p.o
[\question]
[answer]
A. `gcc p.o libx.a`

B. `gcc p.o libx.a liby.a`

C. `gcc p.o libx.a liby.a libx.a`
[\answer]
[analysis]
链接器解析引用算法要求定义符号的库必须出现在引用该符号的目标文件之后。

A 场景：p.o 引用 libx. A 中的符号，因此 libx. A 必须放在 p.o 之后。

B 场景：p.o 引用 libx. A 中的符号，libx. A 可能引用 liby. A 中的符号，因此顺序应为 p.o -> libx. A -> liby. A。

C 场景：在 B 场景基础上，liby. A 还依赖于 libx. A 中 p.o 未定义的符号（即存在循环依赖），因此需要将 libx. A 在 liby. A 之后再写一次，以确保链接器在扫描 liby. A 时，其未解析符号能在第二次扫描 libx. A 时得到解析。

# 重定位

## 重定位的概念与步骤

链接器在符号解析之后进行重定位，其步骤分为两步：

1.  重定位节和符号定义：链接器将所有输入模块中相同类型的节（如所有 `.text`）合并为同一个聚合节，并为这些节以及每个符号分配运行时内存地址
2.  重定位节中的符号引用：链接器修改代码节和数据节中对每个符号的引用，使它们指向正确的运行时地址

## 重定位条目

汇编器在生成 `.o` 文件时，若遇到最终位置未知的目标引用，就会生成一个重定位条目，告诉链接器如何修改这个引用

代码的重定位条目放在 `.rel.text` 中，已初始化数据的重定位条目放在 `.rel.data` 中

重定位条目主要包含偏移（需要修改的位置）、符号（指向哪个符号）和类型（如何修改）等信息

## 重定位地址计算

重定位的核心是计算修正后的地址值。对于 PC 相对寻址，公式为：`重定位引用值 = ADDR(r.symbol) + r.addend - ADDR(包含引用的节)`

其中 `ADDR(s)` 表示节或符号的运行时内存地址，`r.addend` 是重定位条目中的加数

[task]
[question]
考虑目标文件 m.o 中对函数 swap 的调用，具有如下重定位条目：r.offset = 0 xa, r.symbol = swap, r.type = R_X 86_64_PC 32, r.addend = -4。

A. 假设链接器将 m.o 中的 .text 重定位到地址 0 x 4004 e 0，把 swap 重定位到地址 0 x 4004 f 8。那么 callq 指令中对 swap 的重定位引用的值应该是什么？

B. 假设链接器将 m.o 中的 .text 重定位到地址 0 x 4004 d 0，把 swap 重定位到地址 0 x 400500。
[\question]
[answer]
A. 引用值为 0 x 0 A

B. 引用值为 0 x 22
[\answer]
[analysis]
重定位引用值计算公式：`ADDR(symbol) + r.addend - ADDR(包含引用的节)`，其中包含引用的节的地址为 `ADDR(.text) + r.offset`。

A 场景：引用值 = 0 x 4004 f 8 + (-4) - (0 x 4004 e 0 + 0 xa) = 0 x 4004 f 4 - 0 x 4004 ea = 0 x 0 A

B 场景：引用值 = 0 x 400500 + (-4) - (0 x 4004 d 0 + 0 xa) = 0 x 4004 fc - 0 x 4004 da = 0 x 22
[\analysis]

# 加载与动态链接

## 可执行文件的加载

加载器将可执行文件的代码和数据段拷贝（或映射）到内存中，然后跳转到程序入口点（`_start`）

程序运行时内存映像包括：只读代码段、可读写数据段（含 `.data` 和 `.bss`）、运行时堆、共享库映射区、用户栈等

## 动态链接概念

共享库（`.so` 或 `.dll`）在运行或加载时，才被加载到内存并与程序链接，此过程由动态链接器执行

共享库的代码和数据的单一副本可被多个进程共享，节省了磁盘空间和内存

动态链接分为加载时链接（程序启动时完成）和运行时链接（程序通过 API 如 `dlopen` 动态加载）

## 位置无关代码

为使共享库代码能被加载到任意内存地址而不需修改，现代系统使用位置无关代码

GCC 使用 `-fpic` 选项生成 PIC 代码，共享库编译必须使用该选项

PIC 关键技术之一是全局偏移表

## 全局偏移表

GOT 是数据段中的一个表，存放全局数据和外部函数的绝对地址

对 GOT 中数据的访问通过 PC 相对寻址实现，动态链接器在加载时重定位 GOT 表项，填入正确的地址

GOT 实现了延迟绑定：函数地址在第一次被调用时才解析和填充，加快了程序启动速度

在动态链接中，共享库的加载地址在编译时未知，因此代码中对这些外部符号的引用不能是绝对地址。

编译器在生成 PIC 代码时，对于外部函数或变量的引用，会生成通过 GOT 进行间接跳转或访问的指令。

动态链接器在程序加载或运行时，负责将共享库的实际加载地址计算出来，并填入 GOT 的相应表项中。

程序执行时，通过访问 GOT 来获得目标地址，从而实现了代码与具体加载地址的解耦。
