# MIPS 下 Linux 系统的启动过程

## MIPS 基本地址空间

32 位下，MIPS 程序地址空间总共 4 G，分为：

![[MIPS程序地址空间结构.png]]

### Kuseg

用户态程序只能访问这一部分。

需要 MMU 和页表将其中的虚拟地址映射到物理地址。

### Kuseg 0

Unmapped：表明不依赖页表。实际上，这一段的虚拟地址去掉最高位后就是物理地址，属于直接映射。

Cached：表明需要 cache 初始化之后才能使用。

### Kuseg 1

Unmapped：不依赖页表。实际上，这个也是直接映射，但是是去掉最高三位才是物理地址。

Uncached：不依赖 cache。因此，这一段代码能在 cache 和 MMU 都没有初始化的时候使用。

基于这两点，我们知道，在机器刚上电时，由于 cache 和 MMU 都没有初始化，我们只能根据这一块的地址找到代码。那么不难分析出，启动的代码当然需要放在这一部分地址中了。

### Kuseg 2

Mapped：表明这一部分需要用 MMU，通过 TLB 将虚拟地址映射到物理地址。因此可映射的范围比 512 MB 大得多。

## Bootloader 阶段

MIPS 一般使用 U-Boot 作为 OS 装载程序。

这里不详细说明这一阶段了（~~其实部分原因我没有完全搞懂，但感觉不太重要？~~）。大概分为两步，第一步为汇编指令，初始化部分硬件后，设置堆栈，然后跳转到第二步 C 语言的入口；第二步为 C 语言，初始化部分外设后，跳转到内核入口。

那如何找到第一步汇编指令呢？根据前面的分析，我们知道可以通过 kuseg 1 中的地址找到。这个地址被规定为 `0xBFC00000`。因为这个地址位于 kuseg 1 中，且对应的物理地址 `0x1FC00000`（抹去虚拟地址的前三位得到）位于 ROM 中，而 ROM 里的内容在断电后不消失！这下一切就串上了！

### lab 1 实验相关

在我们的实验中，把这一阶段用 QEMU 模拟器简化了。QEMU 模拟器用软件来模拟硬件功能，达到类似 bootloader 的效果。

同样地，我们要构建的 MOS 操作系统也是 Linux 操作系统的阉割版，仅基于 MIPS 架构的模拟器中，便于我们学习罢了。

QEMU 模拟器内置了 bootloader 功能，能够直接识别并加载 ELF 格式的内核镜像文件。在 MOS 操作系统的实验中，QEMU 可以直接将 ELF 内核加载到正确的内存位置并跳转执行，因此开发者不需要再单独实现 bootloader 来从磁盘等介质加载内核。这大大简化了实验的启动流程，让学生能够专注于内核核心功能的开发。[\analysis]

## Linux 内核启动阶段

### 第一阶段（汇编指令 head. S）

#### 这个文件对应的就是我们实验中的 start. S

**首先需要清除 BSS**。BSS 是 C 语言等程序的内存布局中，存放**未初始化的全局变量和静态变量**的内存区域。而我们知道，C 语言中，未初始化的全局变量的默认值为 0. 所以必须将这一段内存全部清为 0.

我们实验中已经写好了这一部分代码：

```asm
/* clear .bss segment */
la      v0, bss_start          # 将 bss_start 的地址加载到 v0 寄存器
la      v1, bss_end            # 将 bss_end 的地址加载到 v1 寄存器
clear_bss_loop:
beq     v0, v1, clear_bss_done # 如果 v0 == v1，说明清完了，跳转
sb      zero, 0(v0)            # 将 0 存储到 v0 指向的内存地址（清一个字节）
addiu   v0, v0, 1              # v0 地址加 1，指向下一个字节
j       clear_bss_loop         # 跳回循环继续
```

然后要为后面 C 语言打基础（**设置内核栈**）。

大致代码是这样的：

```asm
la      sp, stack_top
```

在我们的实验中，这段代码需要我们自己填写。我们必须要在 `mmu. h` 文件中找到 `stack_top` 具体的位置。而这个文件里已经画好了内存布局图，其中 ` KSTACKTOP ` 为 ` 0x80400000 `，把这个数字替换掉 ` stack_top ` 即可。

**接下来跳转到 C 语言部分**。

```asm
j       start_kernel
```

我们实验中，这一部分同样需要我们填写。而这个函数的名字在注释中已经给出，是 `mips_init`。

总体来说，和 bootloader 的第一部分很像。确实如此，但是当然还有其他的步骤，只不过我们的实验中省略掉了，我在此也就不深究了（~~原谅我真的学不动了~~）。

### 第二阶段（C 语言函数 `start_kernel() `）

#### 这个文件对应的是我们实验中的 `init/init.c` 文件中的 `mips_init()` 函数。

我们实验中的代码长这样：

```c
void mips_init(u_int argc, char **argv, char **penv, u_int ram_low_size) {
	printk("init.c:\tmips_init() is called\n");
	halt();
}
```

当然还有很多注释掉的内容，要我们之后补充。

总之，这个函数能做很多事，包括：初始化硬件、内存管理、进程管理、文件系统，等等。

而 `halt()` 则是停止 CPU 执行。
