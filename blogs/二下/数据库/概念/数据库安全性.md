# 数据库安全概述

## 安全问题的提出

数据库的一大特点是数据可以共享，但这种共享不能是无条件的。数据库中数据的共享是在 DBMS 统一严格的控制之下进行的，只允许有合法使用权限的用户访问允许他存取的数据。数据共享必然带来数据库的安全问题，数据库安全是指保护数据库，防止因用户非法使用数据库造成数据泄露、更改或破坏等恶意人为破坏问题。

## 安全性的三个目标

- **Secrecy（机密性）**：数据不被未授权的用户获取
    
- **Integrity（完整性）**：数据不被未授权的用户篡改
    
- **Availability（可用性）**：授权用户能够正常访问数据
    

核心问题：哪些用户可以对哪些数据执行什么样的操作？管理员制定访问控制规则，数据库执行规则检查。

# 安全性控制模型

安全性控制的职能分解为：用户标识与鉴别 → 存取控制 → 审计等后续环节。

# 用户标识与鉴别

系统提供一定的方式让用户标识自己的名字或身份，系统内部记录着所有合法用户的标识。每次用户要求进入系统时，由系统核对用户提供的身份标识，通过鉴定后才提供机器使用权。用户标识和鉴定可以重复多次，通常用用户名/口令实现。

# 存取控制

## 存取权限的定义与检查

存取控制分为两步：首先定义存取权限，在数据库系统中预先对每个用户定义存取权限；然后检查存取权限，对于通过鉴定获得上机权的合法用户，系统根据他的存取权限定义对他的各种操作请求进行控制，确保他只执行合法操作。

存取权限由两个要素组成：数据对象和操作类型。

## 权限分类

- **系统权限**：启动、关闭数据库，转储、恢复数据库，创建、删除数据库等
    
- **数据对象权限**：对基本表、视图、存储过程、函数等数据库对象的操作权限，包括列级权限（列的添加、修改、删除等）、行级权限（行的插入、修改、删除等）、连接级权限（连接控制等）
    

# SQL DCL 中的权限控制

## 权限授予（GRANT）

```
GRANT 权限 ON 数据对象 TO 用户 [WITH GRANT OPTION];
```

示例：

- 对指定用户授予表级查询权限：`GRANT SELECT ON TableA TO UserA;`
    
- 限定列级权限：`GRANT SELECT(a, b) ON TableA TO UserA;`
    

## 权限收回（REVOKE）

```
REVOKE 权限 ON 数据对象 FROM 用户;
```

示例：`REVOKE SELECT ON TableA FROM UserA;`

## 创建新用户

```
CREATE USER username IDENTIFIED BY 'password';
GRANT USAGE ON dbname.* TO username@'%';
```

USAGE 权限授予基本的登录数据库和查看数据的权利。

## 权限的传播

只有以下用户才能授予和收回权限：数据对象的创建者、DBA、拥有传播权限的用户。使用 `WITH GRANT OPTION` 可以将权限传播给其他用户，例如：

```
GRANT SELECT ON TableA TO UserA WITH GRANT OPTION;
```

此时 UserA 可以向其他用户授予 TableA 的 SELECT 权限。

# 角色

## 角色的定义

角色是命名的权限集合，使用角色可以方便地进行授权管理。角色可以从属于别的角色，获得别的角色定义的权限（即角色可以继承）。

## 角色分类

- **服务器角色**：系统内建，不可自建
    
- **数据库角色**：可自建
    
- **Public 角色**：代表所有用户都具有的权限集合
    

## 角色的操作

创建角色：`CREATE ROLE roleA;`（当前用户需具备创建角色的权限）

向角色授予权限：

```
GRANT INSERT, DELETE ON tableA TO roleA;
GRANT EXECUTE ON procedureA TO roleA;
```

将角色赋予指定用户：`GRANT roleA TO UserA;`，此时 UserA 就继承了 roleA 的权限。也可以对用户 UserA 赋予 roleA 之外的权限：`SET DEFAULT ROLE ALL TO userA;`
