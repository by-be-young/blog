# 逻辑模型概述

## 逻辑模型的定义

逻辑数据模型是对现实世界的第二层抽象，负责将概念数据模式映射为数据库的逻辑结构。它直接与 DBMS 有关，有严格的形式化定义，以便在计算机系统中实现。通常有一组严格定义的无二义性语法和语义的数据库语言，用来定义和操纵数据库中的数据。

## 逻辑数据模型的三要素

数据结构、数据操作和数据约束。

## 逻辑数据模型的类型

- **层次模型**：用树形结构组织数据，记录之间通过指针链接。
    
- **网状模型**：用网状结构组织数据，允许一个节点有多个父节点，也通过指针链接。
    
- **关系模型**：用二维表结构组织数据，是目前**最主流的逻辑模型**。
    
- **面向对象模型**：将面向对象思想引入数据库，支持对象、类、继承等概念。
    
- **XML 模型**：用 XML 文档结构组织数据，适合半结构化数据。
    

# 关系模型概述

## 关系模型的提出

系统而严格地提出关系模型的是 IBM 公司的E.F.Codd。他在 1970 年发表论文"A Relational Model of Data for Large Shared Data Banks"，之后陆续提出了关系代数和关系演算的概念，以及第一、第二、第三范式和 BC 范式。

## ER 模型与关系模型的对比

ER 模型有很多概念（实体、关系、属性等），适用于描述应用需求，但不适合在计算机上实现（只有数据结构，没有定义数据操作）。关系模型只有一个核心概念——关系（relation），用一组表的集合来描述世界，适合在计算机上实现，能进行高效的数据操作。

## 关系数据库

关系数据库系统是支持关系模型的数据库系统，应用严格的数学方法来处理数据。80 年代后成为最重要、最流行的数据库系统。典型产品包括 Oracle、MySQL、SQL Server、PostgreSQL、PolarDB、TDSQL-C、OpenGauss、人大金仓等。

# 关系数据结构

## 关系的基本概念

关系模型就是用二维表格结构来表示实体及实体之间联系的模型。关系模型是各个关系的框架的集合，包括关系名、属性名、关键字等。关系的框架称为关系模式，关系框架和符合该框架的关系值称为关系实例。

## 关系术语

- **关系**：一张二维表。
    
- **元组**：表中的一行。
    
- **属性**：表中的一列。
    
- **域**：属性的取值范围，是一组具有相同数据类型的值的集合。
    
- **分量**：元组中一个属性的值。
    
- **关系模式**：关系名加属性名的集合，表示为 REL (A 1, A 2, ..., An)。
    

## 笛卡尔积

给定一组域 D 1, D 2, ..., Dn，它们的笛卡尔积为 D 1 × D 2 × ... × Dn = {(d 1, d 2, ..., dn) | di ∈ Di, i=1,2,..., n}。笛卡尔积的每个元素是一个 n 元组，元组的分量是有序排列的。笛卡尔积的基数等于所有域的基数的乘积。

## 关系的定义

笛卡尔积 D 1 × D 2 × ... × Dn 的任一子集称为定义在域 D 1, D 2, ..., Dn 上的 n 元关系。数学上关系是笛卡尔积的任意子集，但在实际应用中关系是笛卡尔积中所取的有意义的子集。

## 关系的性质

- 关系中不允许出现相同的元组。
    
- 关系中元组的顺序（行序）无关紧要，可以任意交换。
    
- 关系中属性的顺序（列序）无关紧要，交换时应连同属性名一起交换。
    
- 同一属性名下的各个属性值必须来自同一个域。
    
- 关系中各个属性必须有不同的名字，不同属性可来自同一个域。
    
- 关系中每一分量必须是不可分的数据项，所有属性值都是原子的，不可"表中有表"。满足此条件的关系称为规范化关系。
    

# ER 模型向关系模型转化【!】

## 转化规则

- **规则 1（实体类型的转换）**：将每个实体类型转换成一个关系模式，实体的属性即为关系模式的属性，实体标识符即为关系模式的键。
    
- **规则 2（二元联系类型的转换）**：
    
    - **1:1联系**：可以合并到任意一端对应的实体关系中，但应考虑哪个实体更常被使用，与常用实体合并。
        
    - **1: N 联系**：合并到 N 端对应的实体关系中（**将 1 端的主键添加到 N 端的关系中**）。如果合并到 1 端，会出现数据冗余且违反主键约束。
        
    - **M: N 联系**：转换为独立的关系模式，主键为两端实体集主键的组合，联系的属性也成为该关系模式的属性。
        
    
- **规则 3（三元联系的处理）**：
    
    - 1:1:1联系：与其中一个实体集合并。
        
    - 1:1:N 联系：与 N 端实体集合并。
        
    - 1:M: N 联系：转换为独立的关系模式，主键为 M 端和 N 端实体集主键的组合。
        
    - M:N: P 联系：转换为独立的关系模式，主键为三个实体集主键的组合。
        
    

# 关系的完整性

## 域完整性

属性值应符合域的取值范围，可用于增强数据类型。对属性值能否为空（NULL）的检查也是域完整性的一部分。空值代表"值未知"或"值不存在"，且 NULL ≠ NULL。

## 实体完整性

实体完整性用主键来约束。实施了实体完整性约束的关系，其主属性应同时满足两个条件：主属性不能为空，主属性取值唯一。原因在于关系对应现实世界的实体集或多对多联系，每条记录对应一个实体或联系，而现实世界中的实体和联系都是可区分的，因此主键作为唯一性标识，其属性不能取空值。

## 参照完整性

在关系模型中，实体及实体间的联系都用关系来描述，因此存在关系与关系间的引用。设 F 是关系 R 的一个或一组属性但不是 R 的键，如果 F 与关系 S 的主键 K 相对应，则称 F 是关系 R 的外键。关系 R 称为参照关系，关系 S 称为被参照关系。参照完整性规则：外键上的取值只能是空值，或等于被参照关系中某个元组的主键值。关系 R 和 S 不一定是不同的关系，外键并不一定要与相应的主键同名。

## 用户定义的完整性

针对某一具体关系数据库的约束条件，反映具体应用所涉及的数据必须满足的语义要求。例如：课程名必须取唯一值、学分只能取值{1,2,3,4}等。
