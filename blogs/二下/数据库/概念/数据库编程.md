# 为什么需要数据库编程

SQL 语言主要用于数据查询和更新，但缺乏变量定义、流程控制等高级编程语言特性，难以担负复杂的数据分析处理任务，代码重用性差，运行效率低。因此需要数据库应用程序来完成对数据的分析处理。

数据库应用程序有两种形式：数据库内部应用程序和数据库外部应用程序。

外部应用程序开发灵活、功能与可移植性更强；数据库内部程序执行效率更高，适用于例行的数据分析维护功能。

# 存储过程

## 存储过程的定义

存储过程是由过程化 SQL 语句书写的过程，经编译和优化后存储在数据库服务器中，使用时只要调用即可。通常将多次重复执行的代码段编写成一个过程保存在数据库中。

## 存储过程的优点

- 是 SQL 和模块化编程的结合，能够完成复杂业务功能
    
- 在创建时进行预编译，可以提高 SQL 执行效率
    
- 位于数据库服务器上，调用时无需通过网络传输大量数据
    
- 可以作为一种安全机制，例如参数化的存储过程可以防止 SQL 注入式攻击
    

## 创建存储过程（MySQL）

```
CREATE PROCEDURE procedure_name([IN|OUT|INOUT] param_name type[,...])
BEGIN
    sql_statement
END
```

- Procedure_name：数据库服务器合法的对象标识
    
- Param_name：用名字标识调用时给出的参数值，必须指定值的数据类型。参数可定义为输入参数（IN）、输出参数（OUT）或输入/输出参数（INOUT），默认为输入参数
    
- Sql_statement：是一个过程化 SQL 块，包括声明部分和可执行语句部分
    

## 删除与调用存储过程

```
DROP PROCEDURE procedure_name;
CALL procedure_name(param_value, ...);
```

使用 CALL 方式激活存储过程的执行。数据库服务器支持在过程体中调用其他存储过程。

## 存储过程中的变量与流程控制

数据库提供过程化编程语言，支持变量声明、流程控制、常用数据库函数与命令，并在过程化编程中嵌入 SQL 语句。

示例：

```
DECLARE v_score INT;
SELECT score INTO v_score FROM sc WHERE cno=55 AND stuid=001;
SET v_score = v_score + 1;
UPDATE sc SET score = v_score WHERE cno=55 AND stuid=001;
```

## 动态 SQL

根据用户输入参数和/或数据库状态，动态确定程序中的 SQL 语句内容。

- PREPARE：组装 SQL 语句
    
- EXECUTE：动态执行 SQL 语句
    

示例：

```
CREATE PROCEDURE count_field(IN FIELDNAME VARCHAR(255), IN FIELDVALUE INT)
BEGIN
    SET @sql = CONCAT('SELECT COUNT(*) FROM stu WHERE ', FIELDNAME, '=?');
    PREPARE stmt FROM @sql;
    SET @fieldvalue = FIELDVALUE;
    EXECUTE stmt USING @fieldvalue;
    DEALLOCATE PREPARE stmt;
END;
```

# 游标

## 游标的定义

SQL 语句以关系为操作对象和操作结果，例如 SELECT 语句返回的行集包括满足 WHERE 条件的所有行。但应用程序有时需要遍历关系表，对每行数据进行单独处理，SQL 语言不能直接实现这样的操作要求。游标就是对 SELECT 查询结果集的一种扩展，提供了一种每次处理一行或一部分行的机制。

## 游标的主要功能

- 定位到结果集中的指定行
    
- 从结果集的当前位置检索一行或多行
    
- 对结果集中当前位置的行进行数据修改
    
- 显示其他用户对结果集中的数据库数据进行的数据更改
    

## 游标编程示例

```
CREATE PROCEDURE stu_count(c_age INT)
BEGIN
    DECLARE p_age INT;
    DECLARE p_c INT;
    DECLARE fetchSeqOk BOOLEAN DEFAULT 0;
    DECLARE my_cursor CURSOR FOR SELECT age FROM t_user;
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET fetchSeqOk = 1;
    
    SET p_c = 0;
    OPEN my_cursor;
    
    WHILE fetchSeqOk = 0 DO
        FETCH my_cursor INTO p_age;
        IF p_age < c_age THEN
            SET p_c = p_c + 1;
        END IF;
    END WHILE;
    
    SELECT p_c AS concat('小于', c_age, '岁的总人数');
    CLOSE my_cursor;
END;
```

游标编程的基本步骤：声明游标变量 → 打开游标 → 循环提取数据 → 关闭游标。

# 自定义函数

示例：输入字符串，输出首字母大写、后面字母小写的结果。

```
CREATE FUNCTION capitalize(input_string VARCHAR(255))
RETURNS VARCHAR(255)
BEGIN
    DECLARE output_string VARCHAR(255);
    SET output_string = CONCAT(UPPER(LEFT(input_string, 1)), LOWER(SUBSTRING(input_string, 2)));
    RETURN output_string;
END;
```

使用方式：`SELECT capitalize(' samPLeSTring');` 或 `SELECT capitalize(stu_name) FROM stu;`

# 触发器

触发器是一种特殊的存储过程，基于一个表创建，当特定事件发生时自动触发执行，不需要用户显式调用。触发器可以分为行级触发器和语句级触发器。

# 数据库访问

## 数据库访问的基本过程

各种高级编程语言都提供访问和操作数据库的类库。以 JDBC 为例，基本过程为：

1. 建立连接（Establish a Connection）
    
2. 创建 SQL 语句（Create SQL Statements）
    
3. 执行 SQL 语句（Execute SQL Statements）
    
4. 获取结果集（Get ResultSet）
    
5. 关闭连接（Close connections）
    

## Python MySQL Client（PyMySQL）

PyMySQL 是在 Python 3. X 版本中用于连接 MySQL 服务器的库，遵循 Python 数据库 API v 2.0 规范。

### 数据库连接

```
import pymysql
db = pymysql.connect(
    host='localhost',
    user='root',
    password='your_password',
    database='testdb',
    port=3306
)
```

### 数据库操作

- 创建表：使用 cursor () 方法获取操作游标，通过 execute () 方法执行 SQL 语句
    
- 插入数据：执行 SQL INSERT 语句
    
- 查询数据：fetchone () 获取单条数据，fetchall () 获取多条数据，rowcount 返回影响的行数
    
- 更新数据：执行 SQL UPDATE 语句后需调用 commit () 提交
    
- 删除数据：执行 SQL DELETE 语句后需调用 commit () 提交
    

### 事务处理

Python DB API 2.0 提供了 commit 和 rollback 两个方法。当游标建立之时，自动开始一个隐形的数据库事务。Commit () 提交游标的所有更新操作，rollback () 回滚当前游标的所有操作，每个方法都开始一个新的事务。

# 对象关系映射（ORM）

## ORM 的产生背景

大多数系统使用关系数据库进行数据管理，并使用面向对象的语言开发上层应用。进行数据存取时必须在对象与二维表间建立映射关系，即对象数据只能扁平化为关系表后才能存储。关系模型建模能力有限，面向对象方法无法贯彻到关系数据库中，应用程序必须嵌入 SQL 语言才能操纵数据库。以上不便被称为"Impedance mismatch"，即阻抗失配。

## ORM 的定义

O-R 映射（对象-关系映射）是指用户开发和维护一个中间件层，负责将对象数据映射到关系数据库的表中。系统中其他模块可以通过 OR 映射层以操作对象的方法操作关系表中的数据。OR 映射对前端开发人员屏蔽了数据库底层细节，使他们可以专注于业务流程的实现，极大提高了应用系统开发的生产率。

## ORM 的两种实现方案

### Active Record

一个对象既包含数据又包含行为，将对象和数据库表看作是一一对应的关系，一个对象对应一个数据库表中的行数据，对象和行数据之间的映射关系由 ORM 框架自动维护。通过对象的属性来操作数据表，例如修改对象的属性后，直接通过 ORM 框架更新到数据库表中。优点是简单、容易理解；缺点是耦合度高、性能较差。

### Data Mapper

将对象和数据库表看作是两个独立的概念，对象类与数据库表之间没有必然的联系，需要手动定义对象属性和数据表的字段之间的映射关系。对象的读写操作不直接与数据库交互，而是通过数据访问对象（DAO）来实现。优点是提供更好的灵活性，选择需要的对象属性进行存储，使得应用层和数据层相对独立，隐藏了彼此的细节，性能较好；缺点是复杂，需要一定的学习成本，部署较为困难。

## ORM 的优点与缺点

**优点**：提高开发效率、数据库平台透明、数据库结构自动维护、代码可读性高。

**缺点**：需要一定的学习成本、存在性能问题、不适用于复杂场景。
