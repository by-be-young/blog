# MIPS 下 Linux 系统的启动过程

## MIPS 基本地址空间【!】

程序地址空间是指**一个进程**所使用的虚拟地址的地址空间，不同进程间的程序地址空间相互独立。也就是说，即使不同进程的虚拟地址一样，其映射的物理地址是不一样的，即数据也不一样。

> **虚拟地址与物理地址**
> 
> 在计组中就学过虚拟地址与物理地址的转换，因此这里仅仅是简要归纳一下：
> 
> 一个程序（进程）所使用的地址均为虚拟地址，为了通过虚拟地址找到物理地址，必须通过一定的规则或者辅助工具（如 MMU）来进行转换。
> 
> 【进程的概念详见本博客网站的“进程管理”一文】

32 位下，MIPS 程序地址空间总共 4 G，分为 `kuseg`, `kseg0`, `kseg1`, `kseg2` 四个部分：

![[MIPS程序地址空间结构.png]]

### Kuseg

用户态程序只能访问这一部分。

需要 MMU 和页表将其中的虚拟地址映射到物理地址。

### Kseg0

- Unmapped：表明不依赖页表。实际上，这一段的虚拟地址去掉最高位后就是物理地址，属于直接映射。

- Cached：表明需要 cache 初始化之后才能使用。

**内核（kernel）代码和数据一般放在这个区域**。这是因为：运行在 kseg1 的 bootloader（后续会说明）在载入内核之前会初始化 cache，因此 cache 可以使用；而 TLB 需要操作系统进行配置管理，在操作系统内核还没运行时，TLB 不可能可用。

[\question]
[options]A kuseg[\options]

[options]D kseg2[\options]
[answer]B[\answer]
[analysis]
MIPS 虚拟地址空间中，kseg0 区域（0x80000000-0x9FFFFFFF）通过 cache 访问，且虚拟地址与物理地址有固定的偏移映射关系（减去 0x80000000 即得物理地址），无需 TLB 转换，非常适合存放内核的代码段、数据段和 BSS 段。这样可以保证内核运行时的效率和确定性，避免 TLB miss 带来的复杂性。[\analysis]
[\task]

### Kseg1

- Unmapped：不依赖页表。实际上，这个也是直接映射，但是是去掉最高三位才是物理地址。

- Uncached：不依赖 cache。因此，这一段代码能在 cache 和 MMU 都没有初始化的时候使用。

基于这两点可知：机器刚上电时，cache 和 MMU 都未初始化，只能通过这一区域找到代码。因此，启动代码必须放在 Kseg1 中。

### Kseg2

- Mapped：表明这一部分需要用 MMU，通过 TLB 将虚拟地址映射到物理地址。因此可映射的范围比 512 MB 大得多。

其中 kseg0 的特点是：只能在内核态访问，虚拟地址减去 `0x80000000` 后直接映射到物理地址的低 512MB 空间，并且使用 cache 进行存取，这使得它成为内核代码和数据的首选存放位置。

## Bootloader 阶段

MIPS 一般使用 U-Boot 作为 OS 装载程序。

这里不详细说明这一阶段了（~~其实部分原因我没有完全搞懂，但感觉不太重要？~~）。大概分为两步：

1. 第一步为汇编指令，初始化部分硬件后，设置堆栈，然后跳转到第二步 C 语言的入口；

2. 第二步为 C 语言，初始化部分外设后，跳转到内核入口。

- **那如何找到第一步的汇编指令呢？**

答：根据前面的分析，我们知道可以通过 kseg1 中的地址找到。这个地址被规定为 `0xBFC00000`。

- **为什么要这么规定？**

答：因为这个地址位于 kseg1 中，且对应的物理地址 `0x1FC00000`（抹去虚拟地址的前三位得到）位于 ROM 中。

- **为什么要位于 ROM 中？**

答：因为ROM 里的内容在断电后不消失！

## Linux 内核启动阶段

### 第一阶段（汇编指令 head. S）

#### 这个文件对应的就是我们实验中的 start. S

- **首先需要清除 BSS**。

BSS 是 C 语言等程序的内存布局中，存放**未初始化的全局变量和静态变量**的内存区域。而我们知道，C 语言中，未初始化的全局变量的默认值为 0. 所以必须将这一段内存全部清为 0.

我们实验中已经写好了这一部分代码：

```asm
/* clear .bss segment */
la      v0, bss_start          # 将 bss_start 的地址加载到 v0 寄存器
la      v1, bss_end            # 将 bss_end 的地址加载到 v1 寄存器
clear_bss_loop:
beq     v0, v1, clear_bss_done # 如果 v0 == v1，说明清完了，跳转
sb      zero, 0(v0)            # 将 0 存储到 v0 指向的内存地址（清一个字节）
addiu   v0, v0, 1              # v0 地址加 1，指向下一个字节
j       clear_bss_loop         # 跳回循环继续
```

- 然后要为后面 C 语言程序打基础（**设置内核栈**）。

大致代码是这样的：

```asm
la      sp, stack_top
```

在我们的实验中，这段代码需要我们自己填写。我们必须要在 `mmu. h` 文件中找到 `stack_top` 具体的位置。而这个文件里已经画好了内存布局图，其中 ` KSTACKTOP ` 为 ` 0x80400000 `，把这个数字替换掉 ` stack_top ` 即可。

- **接下来跳转到 C 语言部分**。

```asm
j       start_kernel
```

我们实验中，这一部分同样需要我们填写。而这个函数的名字在注释中已经给出，是 `mips_init`。

C 语言中，未初始化的全局变量和静态变量被存放在 **. Bss** 段（Block Started by Symbol）。该段在程序加载时由操作系统分配内存并初始化为 0，但不占用可执行文件的磁盘空间（仅记录大小）。已初始化的全局变量存放在 **. Data** 段，局部变量在运行时分配在 **栈** 段，动态分配的内存来自 **堆**。[\analysis]

### 第二阶段（C 语言函数 `start_kernel() `）

#### 这个文件对应的是我们实验中的 `init/init.c` 文件中的 `mips_init()` 函数。

我们实验中的代码长这样：

```c
void mips_init(u_int argc, char **argv, char **penv, u_int ram_low_size) {
	printk("init.c:\tmips_init() is called\n");
	halt();
}
```

当然还有很多注释掉的内容，大概是后续的实验才进行完善。

总之，这个函数能做很多事，包括：初始化硬件、内存管理、进程管理、文件系统，等等。

而 `halt()` 则是停止 CPU 执行。

# x86 下 Linux 系统的启动过程

## BIOS

与 MIPS 架构类似，上电后，第一条要执行的指令也是存放在 ROM 中的，称为 BIOS。计算机同样设置了一个固定的地址，即 BIOS 入口。BIOS 为 `x86` 指令。

### 功能

- 上电自检

BIOS 的作用之一是上电自检（Power-On Self-Test/POST），可以检查计算机的硬件。

- 设置读取顺序

用户可以通过 BIOS 选择通过哪个设备引导电脑启动 (Boot Device)，甚至实现了图形化界面供人机交互。

- 调用磁盘第一个扇区到内存

这里不赘述磁盘的具体结构了，只需要知道第一个扇区存放的是 MBR 即可。BIOS 在检验这个扇区确实是 MBR 之后，跳转到内存中，开始执行 MBR 的指令。

## MBR

MBR（Master Boot Record），中文名称为主引导记录。

MBR 一共只有 512 B，前 446 B 为 bootloader 代码（`x86` 指令），后 64 B为硬盘分区表，最后 2 个字节为魔数。上面说的 BIOS 检验是不是 MBR 就是靠这两个字节。

### Bootloader

1. 扫描后面的硬盘分区表，查找被标记为活动分区的表项。
2. 查找到后，将该表项对应的 VBR 加载到内存。
3. 跳转到内存，执行该 VBR。

> - MBR 和 VBR
> 
> MBR（Master Boot Record），主引导记录，为整个硬盘的第一个扇区，一个硬盘只有一个；
> 
> VBR（Volume Boot Record），卷引导记录，为一个分区的第一个扇区，一个硬盘有多个分区，故有多个 VBR。
> 
> 这两个都属于 Boot Sector（引导扇区）。

### 硬盘分区表

记录磁盘的各个分区的起始位置等信息，并标注哪个分区为活动分区。

此时，如果 Windows 系统的扇区为活动分区，最终就会引导 Windows 操作系统；如果是 Linux 的扇区为活动分区，最终就会引导 Linux 操作系统。所以这是一个通用的过程。当然，这也不是一蹴而就的过程：

## 内核启动

VBR 中的代码加载引导管理器（如 GRUB）到内存，引导管理器从文件系统读取压缩的内核文件 `vmlinuz` 和初始内存文件系统 `initramfs` 到内存。内核启动后，经过一系列其他步骤，最后执行第一个用户空间进程 `/sbin/init`。最后，才终于到了用户登录环节。
